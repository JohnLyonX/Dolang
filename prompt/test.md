# Code Review Context
Mode: Interpreter/Compiler review — DaoLang
Stack: Rust / 解释型脚本语言
Focus: 语言正确性、运行时安全、错误体验、跨平台兼容

## Behavior
- 通读全部相关模块后再评论，不要孤立看单个文件
- 按严重程度分级：critical > high > medium > low
- 每个问题必须附带修复建议或示例代码
- 区分「语言设计问题」和「实现问题」

## Review Checklist

### Lexer
- [ ] 非法字符是否报错（不能 panic 或静默跳过）
- [ ] 字符串未闭合、注释未闭合的边界处理
- [ ] 行列号追踪是否准确（影响错误信息质量）
- [ ] Unicode / 多字节字符是否安全处理

### Parser
- [ ] 语法错误信息是否包含行列号 + 期望 token
- [ ] 优先级和结合性是否正确（尤其是混合运算）
- [ ] 递归深度是否有保护（防止栈溢出）
- [ ] 边界输入：空文件、只有注释、单个 token

### AST
- [ ] 节点设计是否完整覆盖所有语法结构
- [ ] 位置信息（span）是否保留，用于错误定位

### Interpreter / Eval
- [ ] 变量未定义时是否有清晰报错
- [ ] 类型不匹配的运行时错误是否友好
- [ ] 除零、溢出等数值边界是否处理
- [ ] 递归是否有深度限制（防止栈溢出）
- [ ] $break / $continue 在循环外使用是否报错
- [ ] $# 在函数外使用是否报错

### 作用域 / 环境
- [ ] 变量遮蔽（shadowing）行为是否符合设计
- [ ] 函数作用域隔离是否正确
- [ ] 常量重赋值检测是否覆盖所有路径

### 错误处理
- [ ] 所有错误路径是否返回 Result，而不是 unwrap/panic
- [ ] 错误信息是否对用户友好（行号、变量名、期望值）
- [ ] 错误是否可以继续恢复（REPL 场景下不能因单行错误退出）

### REPL
- [ ] Ctrl+C / Ctrl+D 是否正确处理
- [ ] 多行输入的括号匹配检测是否准确
- [ ] 历史记录是否正常工作
- [ ] 跨平台终端兼容（Windows / Unix）

### 跨平台
- [ ] 是否有 Unix 专有 API（os::unix、termios、libc）未做 cfg 隔离
- [ ] 路径处理是否使用 PathBuf 而非字符串拼接
- [ ] 行尾符 \r\n 是否正确处理

### 性能
- [ ] 字符串是否有不必要的 clone()
- [ ] 热路径（eval 循环）是否有明显的性能问题
- [ ] 大数据/深递归的压力边界是否测试过

### 测试覆盖
- [ ] 每个语法结构是否有对应测试
- [ ] 错误路径是否有测试（不只测试 happy path）
- [ ] 回归测试：已修复的 bug 是否有对应用例

## Output Format
按文件分组，每个问题格式如下：

**[severity] 文件名:行号**
- 问题描述
- 风险/影响
- 建议修复方案（附代码示例）
